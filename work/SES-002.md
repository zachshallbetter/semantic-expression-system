# SES-002 — Formalize conformance fixtures

Status: Completed — structurally validated

## Intent

Turn the canonical SES-001 fixture plan into machine-readable positive and negative fixture records without implementing a renderer or product behavior.

## Objective

Create a fixture pack covering the four cross-language `Home` reference vectors and the declared negative cases, with each fixture mapped to an SES-001 invariant and expected validation outcome.

## Owner

`coordinator.local`

## Dependencies

- `docs/09-conformance-baseline.md`
- `docs/conformance/ses-001-matrix.json`
- `docs/schemas/ses-schema.ts`
- `docs/schemas/ses.schema.json`

## Acceptance

- Every positive and negative fixture in the SES-001 plan has a stable ID.
- Every fixture identifies its validation layer, baseline invariant, expected result, and failure condition where applicable.
- Positive fixtures share semantic identities and operations while allowing expression topology to differ.
- Negative fixtures fail for the declared reason rather than merely being malformed JSON.
- No renderer, product screen, transport, persistence, or external integration is added.

## Evidence

- Machine-readable fixture files.
- Fixture index with baseline and source references.
- Structural validation output.
- Negative-fixture result records showing expected failures.

## Permissions

Local repository files only. No push, deploy, publish, spend, external communication, or promotion.

## Stop conditions

Stop if the canonical SES-001 matrix contradicts the fixture plan, if a failure condition cannot be represented without inventing runtime semantics, or if validation requires renderer behavior not yet specified.

## Disposition

Completed as a documentation and fixture-pack issue. Evidence is recorded in `evidence/SES-002-evidence.json`. Full JSON Schema execution and runtime negative-fixture evaluation remain follow-on work because the current environment lacks the `jsonschema` package and no validator implementation is in scope.
