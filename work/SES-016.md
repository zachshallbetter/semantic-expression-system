# SES-016 — Add security and trust boundaries

Status: Completed — contract defined

## Intent

Keep expression data declarative and prevent Assets, custom sources, filters, or host extensions from becoming implicit code, authority, or business behavior.

## Acceptance

- Trust classes distinguish declarative data, resources, constrained custom expression, executable behavior, and authority-bearing input.
- Custom sources and host extensions require explicit capability and provenance.
- Resource and execution limits are assigned to host policy.
- Unknown or unsafe expression inputs fail closed.
- No security adapter, sanitizer, sandbox, or remote delivery implementation is added.

## Evidence

- `docs/21-security-trust-boundaries.md`
- `docs/conformance/security-trust-boundaries.json`

## Disposition

Accepted as a protocol-neutral security boundary. Host and delivery protocols must supply environment-specific enforcement.
