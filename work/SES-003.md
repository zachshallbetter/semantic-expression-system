# SES-003 — Close schema/conformance gaps

Status: Completed — contract defined

## Intent

Define the validator-level obligations that cannot be expressed by the current record-shape schemas alone.

## Acceptance

- Cross-record identity, Slot/Socket compatibility, recipe targets, token/assets, operation exposure, accessibility, and responsive reachability have explicit checks.
- Checks have deterministic ordering, stable IDs, typed failure codes, and evidence requirements.
- The contract distinguishes schema validation from conformance validation.
- No validator, renderer, runtime, or product behavior is implemented.

## Evidence

`evidence/SES-003-evidence.json` records the source trace, check families, result-format boundary, and limitations.

## Disposition

Accepted as a specification-only contract. SES-006 owns the final machine-readable result envelope; SES-013 or a later implementation issue may implement the checks.
