# SES-009 — Specify accessibility-preserving expression

Status: Completed — contract defined

## Intent

Ensure expression freedom cannot silently remove accessibility names, relationships, order, focus, operation access, state meaning, or non-visual fallbacks.

## Acceptance

- Accessibility invariants cover names, roles, relationships, order, operations, focus, states, reduced motion, and high contrast.
- Visual freedom and accessibility constraints are explicitly separated.
- Required evaluation contexts and typed failure codes are defined.
- Missing evaluator capability remains inconclusive rather than passing.
- No host framework or renderer implementation is prescribed.

## Evidence

- `docs/15-accessibility-expression.md`
- `docs/conformance/accessibility-expression.json`

## Disposition

Accepted as an accessibility expression contract. Execution remains future validator and host-evaluator work.
